# Architecture

## Part 2.5A scale layer

`ScaleCatalog` loads six validated `ScaleProfile` records from `config/nullstar/scales.json`. STANDARD resolves the existing definition; TITANIC/APOCALYPSE generate longer authoritative phases, deterministic larger barrage locations and annular secondary waves. Independent scene/structure/beam/shockwave descriptors remain cosmetic. Server caps, exact-target confirmation, replay/permissions/cooldown/targeting and pre-reservations precede admission. Snapshot scale/profile/caps are immutable per event. Details and limits: `PART25_ENGINEERING_REPORT.md`.

`CraterGeometry.forCue` is shared by actual execution, plan accounting and inert footprint inspection. `ImpactFootprint` also clips colossal child centers/radii inside the permitted overall physical envelope, including integer rounding; STANDARD's existing pattern is preserved. Radius-500/depth-96 Helios is real geometry, not a smaller crater hidden under effects. `basin` adds broad seeded depth irregularity; `ring` excludes an explicit inner annulus. `DestructionJob` uses constant-memory, world-chunk-aligned tiles/columns and validated checkpoints, caching each column's geometry interval. Missing columns fast-forward logical cells while charging every candidate. The round-robin manager still shares one global candidate budget and a cooperative deadline; later waves wait on lower-wave queued work. The per-event changed-block ceiling is enforced inside the mutation visitor. Diagnostics/history are bounded; chunk counts describe tile visits over passes, not distinct worldwide chunks.

Optional per-world `data/nullstar-jobs-v1.json` checkpoints restore already-queued terrain work after graceful restart, under current radius/depth/apocalypse/operator/concurrency policy. Recovered work pauses for absent/dead/unauthorized/different-dimension owners and releases capacity on completion. Future cues/timelines/cooldowns are not persisted. This is not a crash-consistent transaction across JSON and chunk saves. No chunks are retained or force-loaded.

`state_v2` / `visual_v2` replace the earlier state/visual wire contracts; request/status remain v1. `ColossalMetadata` sends normalized scene, tier, independent dimensions, script/anchor/nodes, barrage footprint/count, wave/checkpoint/duration and commitment. Representative packets remain below 512 bytes. Cadence stays phase transitions plus one Hz; large events use configurable same-dimension observer range (default 2,048). Join reconstructs current scene/phase; transient accents are not replayed.

`StrikeView.scale()` exposes this contract. `CosmicMontageScene` is a minimal normalized-scene foundation routed before terrain frustum culling; `Canvas.sceneBillboard` maps through the camera basis. `CameraScripts` registers `cosmic_montage`; the sampler keeps camera position at the gameplay camera, excludes the self-avatar generically in the existing Mixin seam and applies frame-local FOV/options. No astronomical terrain queries or teleports occur. Skip/accessibility/disabled camera/screens/lifecycle restoration still apply. Colossal HUD age uses authoritative duration; Glassfall's rail pattern uses server footprint metadata/actual cues.

## Build and ownership

The supplied template was compared with FabricMC's official 26.3 example branch and built before implementation. The project retains its Minecraft/API/Loader/Gradle versions, pins its resolved Loom snapshot to 1.18.3, and replaces unused Kotlin example stubs with Java 25 entrypoints. Kotlin runtime is no longer required. Source sets are split by environment.

`Nullstar` initializes validated config, immutable weapon definitions, item/creative registration, networking, commands and server lifecycle callbacks. `NullstarClient` owns key mappings, presentation state, client preferences and HUD. Client classes and the camera Mixin never load on the dedicated server. Production JAR excludes the `gametest` source set.

## Authoritative execution

`WeaponDefinition` declares targeting, phases, sound IDs, camera preset names, event ticks, impact geometry, presentation metadata and cooldown. Bundled files live in `data/nullstar/weapons`. Operator overrides in `config/nullstar/weapons/<id>.json` are validated before use; invalid data fails startup or retains the prior catalog on reload. Current IDs/behaviors are `helios`, `singularity`, `glassfall`. Adding a fourth behavior currently requires extending the behavior allowlist and dispatch in `WeaponEngine`.

`Timeline` is a pure monotonic server-tick state machine. It delivers cues once, including skipped tick intervals. `WeaponCatalog(Path,double)` scales and validates immutable definitions once at load; activation uses those snapshots without scaling again. The one-argument constructor retains multiplier 1. Scaled stages cap at 2400 ticks; cue offsets map proportionally within each actual scaled stage. `all()` is an unmodifiable view. `ActiveStrike` snapshots the validated definition, dimension key, target, geometry caps, seed, owner and start tick. Mutable state is confined to the server thread. Bundled `data/` JSON is loaded from the classpath, not through data-pack reload; only the named config files override it. Unknown override files and sound IDs produce diagnostics at load.

`WeaponEngine` shares activation between item, typed request and commands. It recomputes item targeting on the server, verifies loaded terrain, dimension, distance, border, owner permissions, protection and cooldown. It prevents overlapping activations by one owner and reserves future destruction jobs before accepting a strike. Preview/config-disabled destruction suppresses both damage and terrain changes.

Each tick advances active timelines, schedules phase sounds, applies Singularity attraction at five-tick intervals, publishes event cues and queues impacts. Once the timeline ends it waits for queued jobs before publishing terminal completion. Owner death/disconnect/dimension change, unloaded target chunk or missing level cancels remaining work. Completed terrain changes persist normally in world chunk storage. Cancellation is not an undo operation.

The controller first designates a target for 200 ticks, then confirms activation. Sneak-use selects the next weapon. Activation key uses the same confirmed-target flow. Commands with explicit coordinates still validate server-side distance, ground, loaded state and permissions.

Preview obeys the same `operatorsOnly` setting as destructive activation. It intentionally emits shared sound/visual cues and consumes the same bounded event slot and cooldown; it never reserves destructive jobs or mutates blocks/entities. Runtime invariant failures are contained per strike and discard its pending work; failed terrain steps still consume their scanned candidate budget. Re-reserving an admitted strike is rejected. Already changed terrain remains persistent after cancellation/failure.

## Terrain and entity safety

`CraterGeometry` provides deterministic angular noise, layered radial falloff, bowls, spheres, ellipsoids, seeded mega-basins and annular cuts. Absolute geometry limits are radius 1,024/depth 384; no noise extends beyond the selected radius. STANDARD server radius/depth caps still clamp at 48. Colossal caps are independently validated and default to public clipping. `DestructionJob` scans chunk tiles incrementally with a deterministic checkpointable cursor; every candidate consumes budget. No giant position list is allocated.

`DestructionManager` round-robins at most 64 candidates per slice across all dimensions within a global candidate cap and cooperative four-millisecond deadline. This deadline is cooperative, not a hard real-time guarantee. Individual block updates/protection callbacks can take longer. Chunk keys/positions are retained, not chunks. Unloaded cells are skipped, never force-loaded or retried indefinitely.

Mutation skips borders/build limits, negative destroy-speed blocks, `nullstar:protected_blocks`, all block entities, vanilla player interaction protection and vetoing protection adapters. `BlockTransformations` changes supported bowl-shell materials without loot generation. Neighbor shape propagation is suppressed to keep the work budget predictable; Part 2 must preserve that boundary if introducing fluid or debris simulations.

`ProtectionHooks.register` returns an `AutoCloseable` registration and vetoes both block and living-entity effects. Hook exceptions deny the operation. This is an integration seam; no third-party claim mod bridge is bundled. Register adapters before admitting player strikes. The configurable `operatorsOnly` default is true.

`EntityEffects` performs bounded-radius living-entity queries, falloff damage/knockback and bounded Singularity attraction. Creative/spectator players are excluded. The mutation count is bounded by `entityBudget`; the underlying vanilla query may still enumerate a dense population. Client packets cannot create damage or force vectors.

Explosion sources identify the online owner as both direct and causing entity. Other-player damage, knockback and attraction require the `pvp` rule and vanilla team permission; self-forces remain allowed, while self-damage follows vanilla attributed-explosion rules. Without a resolved owner, player effects fail closed, while mob effects remain environmental. Public claim hooks continue to veto both kinds of effect.

On server shutdown, the optional terrain-job checkpoint runs before in-memory state is discarded; Minecraft saves changed chunks. With persistence off, pending work is discarded as before. With it on, only already-queued jobs resume. Cooldowns are session-scoped, retained across disconnect within the same server session, and reset on server restart.

## Networking baseline and v2 changes

All contracts use typed `CustomPacketPayload` and `StreamCodec<RegistryFriendlyByteBuf,...>`. Version suffixes constrain schemas. Decoders constrain strings/numbers. Round-trip tests bound representative current packets below 512 bytes. The table below records the original fields; state now uses `state_v2` with `ColossalMetadata`, larger validated dimensions and expanded phase enum, and visual uses `visual_v2` for radius/index expansion. Mixed v1/v2 clients are not supported.

| Channel | Owner/direction | Fields and use |
| --- | --- | --- |
| `nullstar:request_v1` | client -> server | protocol=1, monotonic positive sequence, action 0 acquire/1 activate/2 select/3 cancel/4 skip, known weapon string, preview intent. No target, radius, dimension or damage fields. Four-tick replay/rate gate per connection. |
| `nullstar:status_v1` | server -> owner | selected weapon ID/display name, bounded message, confirmed-target flag/position, remaining cooldown ticks. Target is authoritative. |
| `nullstar:state_v1` | server -> observers | strike/owner UUIDs, dimension, weapon ID/display name/phase, overall and phase ages, phase duration, server tick, target, radius/depth, seed, preview, destruction progress, color/orbital height/particle scale/camera preset, terminal flag. |
| `nullstar:visual_v1` | server -> observers | strike UUID, monotonic cue index, impact/projectile type, server-resolved position, capped radius and duration. Client deduplicates; transient cues are not replayed on join. |

State goes out on phase changes and at most once per 20 server ticks, plus initial and terminal messages. Recipients are owner and same-dimension players within 256 blocks. Join and periodic state resync cover late observers and dimension entry. Owner status updates at one Hz after a selection. No per-block or per-render-frame custom packets. Vanilla chunk updates carry terrain changes.

Broadcast rejects payload types/unassociated strike IDs before enumerating recipients; join snapshots apply the same observer range. Transient client-level reset clears presentation/target but retains authoritative cooldown and its clock baseline. Actual disconnect clears the entire session. Controller aiming/effects/HUD accept either hand.

`ClientStrikeState` interpolates from reception ticks, caps cache size, rejects older state, deduplicates cues and expires state after 100 silent client ticks. During singleplayer pause client visual time pauses too. Disconnect and new client-level identity clear all transient presentation.

## Presentation engine (Part 2)

Everything below is client-only, consumes read-only `ClientStrikeState` snapshots and authoritative `visual_v1` cues, and never feeds back into gameplay. No wire schema changed.

**Materials.** `render/NullstarMaterials` declares RenderPearl pipelines with original GLSL 330 shaders in `assets/nullstar/shaders/core`: additive `energy` (defines `MODE_CORE` fresnel-bright core, `MODE_RIM` silhouette glow, `MODE_FLAT` texture-alpha sprites; two-layer scrolling noise, white-hot bleaching), alpha-blended `smoke`, opaque lit `hull` (directional/sky/rim/specular lighting, texture-alpha emissive seams driven by vertex energy) and `debris` (heat glow). Each blended pipeline also registers an OIT pipeline set, because 26.3 throws if a blended render type is drawn with improved transparency but no OIT pipelines. All pipelines are registered **optional**: a shader failure only logs a warning during reload. The first use verifies compilation on the render thread; if anything is missing, the layers fall back to vanilla `lightning`, `entityTranslucent` and `entitySolid` render types fed by the same vertex stream (unused attributes are ignored by the buffer builder), and the native `EffectRenderer` resumes. A resource reload listener ordered after vanilla shaders re-verifies materials.

**Extraction.** `EffectScene` (a `PresentationLayers.Layer`) is registered on Fabric's `LevelRenderEvents.COLLECT_SUBMITS`. Each frame it builds camera-relative geometry into one bounded `VertexSink` per `Layer` (material slot), then submits one `submitCustomGeometry` per non-empty slot. Sinks are reused across frames, reserve whole primitives (never split quads) and drop excess against fixed per-layer vertex budgets. `Canvas` is the scene-facing API (tubes, annuli, billboards, camera-facing streaks/ribbons, lightning arcs, transformed meshes) with origin-relative float coordinates for precision. `Mesh.Builder` creates immutable procedural meshes once (rings, frustums, shell patches, beveled boxes, crystals, spheres) with Newell normals and size-projected UVs, and per-frame drawing only applies transforms. Strike-level frustum culling uses generous bounds so tall effects are not lost when their anchor is off-screen. A renderer exception latches the native fallback until the next level instead of crashing the client.

**Scenes.** `WeaponScene` implementations (`HeliosScene`, `SingularityScene`, `GlassfallScene`) derive animation deterministically from phase, phase progress, strike age and per-strike seed (`StrikeView`). Glassfall projectiles follow analytic Bézier curves from their rail to the cue's server-resolved impact position, so they cannot drift from authority; trails are analytic samples rather than history buffers. Late joiners, who never receive transient cues, reconstruct impact timing from the authoritative phase. `TargetingScene` draws the holographic ground reticle for the local controller only.

**Cosmetic particles and debris.** `CosmeticParticles` is a struct-of-arrays pool allocated once at 1,024 entries; the active cap follows the quality preset (96/384/1,024) multiplied by particle intensity (zero disables). Debris, embers, dust, sparks, crystal shards and motes simulate at 20 Hz with interpolation. Debris bounces on the client heightmap (no collision with entities, no block changes, no chunk loading) and is tinted with the struck block's map colour. Particles are owner-tagged; a strike that disappears before impact (cancellation) purges its cosmetic work.

**Audio.** Twenty-eight original synthesized sound events are registered in common code (`NullstarSounds`) so weapon JSON phase sounds resolve on dedicated servers. `SoundScheduler` delivery is unchanged: one server sound per phase transition goes to same-dimension observers within 256 blocks, deliberately bypassing vanilla's player-position filter because the cinematic listener can be far from the player; charging sources sit at the orbital/core position and impacts on the ground. `CinematicAudio` adds client accent layers (ring locks, collapse cues, per-projectile launch/whistle/strike, aftershocks delayed by listener distance at ~17 blocks/tick) triggered on phase-progress crossings and once per cue index, so resyncs and late joins never replay them. At most ten accent instances play concurrently; the cinematic-audio preference scales or disables them, and vanilla sound categories still apply.

**Camera.** `CameraPreset.Frame` gained roll and continuous rumble (three-argument constructor retained). `CinematicCamera` smooths position and look-at separately so fast subjects stay framed, applies radius-proportional impact shake, FOV punch and roll noise, rejects non-finite or null frames, and lifts desired positions out of solid terrain. `CameraScripts` registers the authored shot vocabulary used by the weapon JSON (`helios_establish/mechanism/discharge/follow/impact/aftermath`, `singularity_form/pull/implode/aftermath`, `glassfall_reveal/lattice/barrage/final/aftermath`). Shots reuse scene choreography (collector height, beam head, crystal flight), keep a stable per-strike heading on the player's side, add a monotonic occlusion lift when foliage or terrain blocks the subject, and decline (normal view) for targets under a thick solid ceiling. The original `orbital`, `beam` and `impact` presets remain for operator overrides. The Mixin seam is unchanged except that it also applies roll by rotating the camera quaternion about its view axis and recomputing the basis vectors.

**HUD and settings.** The controller HUD shows weapon icon, name, state, a segmented phase timeline proportional to stage lengths, terrain progress, recharge bar, an animated reticle with lock contraction, out-of-range state and a designation-expiry countdown, a compact weapon selector and abort/complete banners. A screen-effects layer adds an eased letterbox during directed shots (vanilla crosshair and hotbar are hidden while it is active), a weapon-tinted vignette and the impact wash, which under reduced flashing is a soft low-alpha tint rather than a white frame. `NullstarSettingsScreen` (default key N) edits client preferences and saves `client.json`; it cannot affect server limits.

**Quality and accessibility.** LOW keeps restrained custom geometry and re-enables the native particle layer; MEDIUM and ULTRA scale segment counts, layer counts, trail lengths and particle caps. Accessibility overrides quality: reduced motion disables camera motion and shake while all world effects still play from the player's view; reduced flashing caps flash billboards and the screen wash; screen distortion toggles heat/lens shells; glow intensity scales additive alpha; particle intensity zero removes cosmetic particles. Observers never have their camera taken.

## Camera contracts

`CinematicCamera.register(id, CameraPreset)` registers generic samplers. Only the owner's event activates camera effects. The client-only Mixin applies a pose after vanilla alignment and FOV calculation but before view matrices, culling and perspective projection. It updates camera position, rotation, roll and frame FOV, marks extracted cinematic views detached, and suppresses held-item rendering through that frame's extracted camera-type state. Vanilla recomputes the original state every frame. It never changes the player, camera entity, saved options, input state, server position or control authority. Skip stops only that client's camera; gameplay continues. Disabling the camera, reduced motion, opening screens, death, cancellation, stale snapshots and level changes restore normal view with a 12-tick eased release.
