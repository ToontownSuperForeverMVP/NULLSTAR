# NULLSTAR Part 2 release report

**Decision: PASS with documented open items.** The three weapons keep their validated server-authoritative gameplay and now run on an original cinematic presentation layer. Open items need a human or an environment this machine does not have (listening/viewing approval, multiple independent clients, third-party mods).

## 1. Revision

Branch `part2/cinematic-release`, based on tag `codex/part-1.5b-complete` (`5ba60f1`). Release source and evidence: commit `b181042` (code identical to the JAR build); tag `part2-release` marks the final documentation commit.

## 2. Visual systems

- `render/NullstarMaterials`: six optional RenderPearl pipelines (energy core/rim/flat, smoke, hull, debris) with OIT variants (18 compiled programs), verified on first use, with vanilla render-type fallbacks.
- `render/EffectScene`, `Canvas`, `VertexSink`, `Layer`: per-frame extraction into bounded, reused per-material sinks submitted through Fabric `COLLECT_SUBMITS`; strike-level culling; a failure latch that restores native particles instead of crashing.
- `render/Mesh`: procedural mesh builder (rings, frustums, shell patches, boxes, crystals, spheres), built once and drawn by transform.
- `render/CosmeticParticles`: a 1,024-entry struct-of-arrays pool (debris, embers, dust, sparks, shards, motes) with heightmap bounce, terrain-colour tinting and owner-scoped cancellation cleanup.
- Scenes: `HeliosScene`, `SingularityScene`, `GlassfallScene`, `TargetingScene`, plus the shared `Fx` library (layered beam, shock rings, pressure walls, ground glows, bursts).
- HUD: `NullstarHud` (panel, phase timeline, reticle, selector, banners, letterbox, vignette, impact wash) and `NullstarSettingsScreen`.

## 3. Authored assets (all original, reproducible)

Generated by `tools/assets/generate_textures.py` (numpy/Pillow, fixed seeds): `effect/plasma, flow, glow, shock, smoke, void, halo, crystal, rubble`; hull sheets `machine/helios_hull, glassfall_hull, singularity_hull` (irregular panel subdivision, bevels, rivets, vents, accent stripes, emissive seams in alpha); `item/controller`; `gui/weapons` icons; the mod `icon.png`. Machinery geometry is procedural code (`Mesh.Builder`) in the scene classes. The shaders `energy`, `smoke` and `hull` (`.vsh/.fsh`) were written for this project.

## 4. Audio assets and provenance

28 mono 44.1 kHz Ogg Vorbis files (about 640 KB) synthesized by `tools/assets/generate_audio.py` from oscillators, FFT-filtered noise, inharmonic metal partials, sweeps, crackle and synthetic convolution reverb, mastered to -3 dBFS before encoding. No recordings or third-party samples are used. Palettes: Helios (activate, charge with pulses, align servos and clanks, ring lock, reactor pulse, discharge, descent rush, impact, aftershock, smoulder, shutdown); Singularity (detuned activation, beating gravitational charge, rising inward swirl that cuts to silence, collapse, inhale and implosion with secondary crack, resonant aftermath); Glassfall (chime, crystalline resonance, lattice ticks, rail charge, launch zap, descending whistle, crack-and-shatter strike, fracture-and-boom finale, tinkling aftermath); UI (lock, select). `validate_audio.py` confirms format, headroom and that every file is referenced. They were reviewed by spectrogram only, **not by listening**.

## 5. Rendering architecture changes

Client-only additions under `client/render`, `client/camera`, `client/audio`. Common code gained only `NullstarSounds` (sound event registration). Weapon JSON changed only in camera preset names and sound IDs. No network payload, server engine, destruction or protection code changed. Details: `ARCHITECTURE.md` › Presentation engine.

## 6. Camera improvements

Fifteen authored presets cover establishing/reveal, mechanical detail, discharge, follow, impact and aftermath crane shots per weapon. Other changes: `Frame` roll and rumble; separate position and look-at smoothing; radius-proportional impact shake with FOV punch; terrain clearance; a monotonic occlusion lift; a stable per-strike heading on the player's side; and declining frames for targets under thick ceilings. The Mixin seam adds only roll. Restoration paths are unchanged and covered by tests.

## 8. Graphics presets

LOW keeps restrained geometry and the native particle layer, with about a 96-particle cosmetic cap. MEDIUM is the default (cap 384, about 0.67 geometry detail). ULTRA raises the cap to 1,024 and uses full segment, layer and trail detail. Accessibility settings (reduced motion, reduced flashing, which is on by default, particle intensity including zero, distortion, glow, audio, letterbox) override quality.

## 9. Performance

Measured on an RTX 2000 Ada / EPYC 9354 machine (see `VALIDATION.md`). A single ULTRA strike extracts in 0.08–0.45 ms per frame, with at most 2.6 ms of measured frame render work and about 22k vertices at the impact peak. Four concurrent synthetic strikes extract in at most 0.85 ms, with at most 3.4 ms of render work; budgets dropped excess vertices and the particle cap held at 1,024. Server average tick time stayed at or under 2.3 ms during real destruction. FPS readings are capped at 30 when the test window is unfocused, so they are not used as evidence; focused runs showed 96–120 FPS.

## 12. Known limitations

- Gravitational lensing and heat shimmer are geometric illusions; 26.3 post chains offer no supported dynamic-uniform seam without additional mixins.
- Debris collides only with the client heightmap.
- Shots lift above occluders rather than path-planning, and decline for caves.
- The ground reticle shows the bundled radius, so operator overrides can differ visually.
- Late joiners rebuild impact timing from phases, so they miss transient-only accents.
- Unverified: human art/audio approval, multiple independent graphical clients and late observers, third-party render/shader/claim mods, survival-owner death in every phase, and dense-world timing.

## 13. Dependencies

Minecraft 26.3, Java 25, Fabric Loader ≥ 0.19.5, and Fabric API 0.162.0+26.3, on both client and server. No other runtime dependency. Asset tooling, which is not needed to play, uses Python 3 with numpy, Pillow and soundfile.

## 14. Installation

Copy `build/libs/nullstar-1.0.0.jar` (not the `-sources.jar`, not the test mod) and Fabric API into the 26.3 Fabric instance's `mods` folder on the client and server. In game, `/nullstar give` provides the controller; N opens visual settings.
